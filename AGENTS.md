# Hack the School

Веб-прототип каталога факультативов ВШБ на React, TypeScript, Vite и Chakra UI.

## TDD

При добавлении или изменении поведения работай по одному сценарию за цикл.

1. **Красный.** Добавь или обнови тест с ожидаемым результатом из требования. Запусти его и проверь, что он падает на нужном поведении.
2. **Зелёный.** Внеси минимальное изменение, которое даёт ожидаемый результат. Запусти тот же тест и убедись, что он проходит.
3. **Рефакторинг.** Если код можно упростить, сделай это на зелёных тестах. Повтори прогон перед переходом к следующему сценарию.

Храни `*.test.ts` и `*.test.tsx` рядом с проверяемым кодом. В UI-тестах используй `renderWithChakra` из `src/test/render.tsx`, находи элементы по роли и доступному имени, а действия пользователя воспроизводи через `user-event`. Проверяй результат, который видит пользователь, например список курсов после выбора темы. Для правил предметной области проверяй результат публичной функции. В тестах правил дедлайна передавай текущее время явно.

## Проверки

- `npm test -- src/App.test.tsx` — пример прогона одного файла.
- `npm run test:watch` — повторять прогон при изменении файлов.
- `npm test`, `npm run lint`, `npm run build` — проверки перед завершением изменений в коде. Их же запускает GitHub Actions.
- `npm run test:visual` — сравнение интерфейса с PNG-эталонами в Playwright. Обновляй эталоны только при ожидаемом изменении интерфейса, в Linux-образе из раздела «Скриншотные тесты» в `README.md`.

## Ветки и слияние

- Создавай отдельную ветку от актуальной `main` для каждой задачи. Включай в ветку только изменения, нужные для этой задачи.
- Вливай изменения в `main` через pull request из этой ветки.
- Перед слиянием дождись зелёных заданий `check` и `visual` в GitHub Actions `CI` для последнего коммита PR. После нового пуша дождись результата нового прогона.
